# Этапы внедрения TanStack Query и Zustand

С учетом текущего `dashboard` и API-роутов:

## 1) Установка и базовая инициализация

- Установить зависимости:
  - `@tanstack/react-query`
  - `@tanstack/react-query-devtools`
  - `zustand`
- Создать `QueryClientProvider` в клиентском провайдере (обычно `app/providers.tsx`).
- Подключить провайдер в `app/layout.tsx`.
- Задать базовые `defaultOptions` (`staleTime`, `retry`, `refetchOnWindowFocus`).

## 2) Определить границы state

Перед началом кодинга зафиксировать карту состояния:

- **Server state**:
  - `daily meals`
  - результаты поиска блюд
  - CRUD-операции над сущностями
- **Client/UI state**:
  - открытие/закрытие модалок
  - локальные фильтры `dashboard`
  - сортировка
  - временные значения форм

## 3) Сделать слой API-функций

- Вынести `fetch`-функции в отдельный модуль (например `src/shared/api/meals.ts`).
- Типизировать вход и выход.
- Использовать эти функции и в `query`, и в `mutation`.

Это уменьшит дублирование и упростит тестирование.

## 4) Первое внедрение TanStack Query на одной фиче

Лучше начать с `dashboard`:

- Заменить ручную загрузку списка на `useQuery`.
- Создать стабильные `query keys` (например `['daily-meals', date]`).
- Добавить обработку `isLoading` и `isError`.

## 5) Внедрить mutations

Для добавления, удаления и обновления:

- Использовать `useMutation` для `POST/DELETE/PATCH`.
- После успеха вызывать `invalidateQueries` для нужных ключей.
- При необходимости добавить `optimistic update` для более быстрого UX (например в `AddMealModal`).

## 6) Подключить Zustand для UI

Создать небольшие фиче-сторы, например:

- `useDashboardUiStore`:
  - `modal open/close`
  - текущие фильтры
- `useMealDraftStore`:
  - черновик формы (если нужен между компонентами)

Держать сторы узкими и не хранить в них данные сервера.

## 7) Интеграция с Next.js App Router

- Серверные компоненты оставить для SSR-скелета и роутинга.
- Интерактивные части (`AddMealModal`, фильтры, таблицы) делать `client components` с Query/Zustand.
- Если позже потребуется SSR-prefetch, добавить `dehydration/hydration` как второй этап оптимизации.

## 8) Devtools и контроль качества

- Включить React Query Devtools в dev-режиме.
- Проверить сценарии:
  - первый вход
  - добавление блюда
  - удаление блюда
  - повторный вход на страницу
  - обработка ошибок API
- Убедиться, что нет лишних повторных запросов.

## 9) Постепенная миграция

Не переписывать все сразу:

`1 фича -> стабилизация -> следующая фича`

Так внедрение пройдет безопасно и без поломки текущего функционала.

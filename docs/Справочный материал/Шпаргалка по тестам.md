Ниже компактная шпаргалка по Jest + React Testing Library (как раз про findByTestId, toHaveTextContent, toHaveBeenCalled, getByRole, mockResolvedValue и похожие).

1) Поиск элементов (queries)
getBy... — сразу ищет элемент; если не найден → кидает ошибку.
Используй, когда элемент должен быть уже в DOM.
queryBy... — ищет элемент, но если не найден → null (без ошибки).
Удобно для проверок “элемента нет”.
findBy... — асинхронный поиск (Promise), ждёт появления элемента.
Используй после загрузки данных/рендера по async.
Примеры:

screen.getByRole('button', { name: /save/i })
screen.queryByText(/error/i)
await screen.findByTestId('meal-card')
2) Самые частые selectors
getByRole(role, { name }) — предпочтительный способ (ближе к реальному UX и accessibility).
getByLabelText — для инпутов с label.
getByPlaceholderText — если ориентируешься на placeholder.
getByText — по тексту на странице.
getByTestId / findByTestId — запасной вариант, когда роли/текста недостаточно.
3) Матчеры (assertions)
Из @testing-library/jest-dom:

toBeInTheDocument() — элемент есть в DOM.
toHaveTextContent(text) — содержит текст.
toHaveValue(value) — значение инпута.
toBeDisabled() / toBeEnabled()
toBeVisible()
toHaveAttribute(attr, value)
toHaveClass(className)
Из Jest:

toBe(...) — строгое сравнение примитивов.
toEqual(...) — глубокое сравнение объектов/массивов.
toHaveBeenCalled() — мок-функция вызывалась.
toHaveBeenCalledTimes(n) — сколько раз вызывалась.
toHaveBeenCalledWith(...) — с какими аргументами.
4) Моки и стабы (Jest mocks)
jest.fn() — создать мок-функцию.
jest.mock('module') — замокать модуль.
mockReturnValue(value) — синхронный возврат значения.
mockResolvedValue(value) — вернуть Promise.resolve(value).
mockRejectedValue(error) — вернуть Promise.reject(error).
mockImplementation(fn) — своя реализация.
jest.clearAllMocks() — сброс истории вызовов (обычно в beforeEach).
Пример:

api.getMeals = jest.fn().mockResolvedValue([{ id: 1, name: 'Soup' }])
expect(api.getMeals).toHaveBeenCalled()
5) Async-паттерны
await screen.findBy... — дождаться появления элемента.
await waitFor(() => expect(...)) — ждать, пока условие станет true.
waitForElementToBeRemoved(...) — дождаться исчезновения элемента (например, loader).
Для проверок ошибок промисов:
await expect(fn()).rejects.toThrow(...)
6) События пользователя
const user = userEvent.setup()
await user.click(button)
await user.type(input, 'text')
await user.selectOptions(select, 'value')
userEvent лучше, чем fireEvent, для реалистичных пользовательских действий.

7) Мини-правила “что когда использовать”
Элемент должен быть сразу → getBy...
Элемент может отсутствовать → queryBy...
Элемент появится позже → findBy...
Проверяешь вызовы функций/API → toHaveBeenCalled...
Мокаешь async API → mockResolvedValue / mockRejectedValue
В приоритете getByRole, getByLabelText; testId — когда другие селекторы неудобны.

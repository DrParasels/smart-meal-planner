# 🚀 Этап 1 — Профиль пользователя

## Цель
Собрать параметры пользователя и рассчитать дневную норму калорий.

## Нужно реализовать

- Страница onboarding (/onboarding)
- Форма:
  - Рост
  - Вес
  - Возраст
  - Пол
  - Уровень активности
  - Цель (похудеть / поддерживать / набрать)
- Сохранение профиля в БД
- Расчёт BMR
- Расчёт дневной нормы калорий
- Перенаправление на dashboard

## Критерий готовности

Пользователь:
- Заполняет профиль
- Видит рассчитанную норму калорий
- Может зайти на dashboard

---

# 🚀 Этап 2 — Recipe Model

## Цель
Создать структуру рецептов и ингредиентов.

## Нужно реализовать

- Модель Recipe
- Модель Ingredient
- CRUD для рецептов (минимум — создать вручную несколько рецептов)
- Связь Recipe ↔ Ingredients
- У каждого рецепта:
  - Калории
  - БЖУ
  - Ингредиенты
  - Описание

## Критерий готовности

В базе есть минимум 10 рецептов.
Можно получить список рецептов через API.

---

# 🚀 Этап 3 — Выбор блюд на день

## Цель
Пользователь может выбрать блюда на завтрак, обед и ужин.

## Нужно реализовать

- DailyMeal модель
- DailyMealItem модель
- Создание записи на текущий день
- Выбор рецепта для:
  - breakfast
  - lunch
  - dinner
- Отображение выбранных блюд на dashboard
- Подсчёт суммарных калорий

## Критерий готовности

Пользователь:
- Выбирает блюда
- Видит итоговые калории
- Видит прогресс (например 1200 / 2100)

# 🚀 Этап 4 — Список покупок

## Цель
Автоматически собрать ингредиенты выбранных блюд.

## Нужно реализовать

- Получить все ингредиенты из выбранных рецептов
- Объединить повторяющиеся
- Показать список
- Отдельная страница /shopping-list

## Критерий готовности

Пользователь нажимает "Сформировать список"
и видит агрегированный список ингредиентов.

## 🚀 Этап 5 — Тестирование

**Цель:** научиться писать актуальные тесты (unit / component / integration / e2e) и внедрить базовую тестовую стратегию в проект.

**Что делаю:**
- настраиваю тестовую инфраструктуру для frontend и backend;
- пишу component/integration тесты для ключевых экранов;
- добавляю unit/e2e тесты backend;
- покрываю критический пользовательский flow в Playwright.

**Критерии завершения:**
- frontend: есть рабочие тесты для onboarding/выбора блюд/dashboard;
- backend: есть unit тесты сервисов и минимум 1–2 e2e сценария API;
- e2e: проходит сценарий registration → onboarding → dashboard;
- все тесты запускаются командами проекта и проходят стабильно.

**Техдолг Stage 5 (отложено):**
- backend: выделить unit-уровень для расчёта калорий в отдельный модуль/сервис;

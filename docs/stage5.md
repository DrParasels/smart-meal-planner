# 🧩 Stage 5 — Тестирование (детальный план)
## Цель этапа
На практике научиться писать современные тесты и понимать, какой тип теста применять в каждом случае:
- unit — для изолированной логики;
- component — для поведения UI;
- integration — для связки модулей;
- e2e — для критичных пользовательских сценариев.
---
## 1) Подготовка окружения тестирования ✅
- [ ] Определить стек:
  - Frontend: Vitest/Jest + React Testing Library + jest-dom
  - Backend: Nest testing + supertest
  - E2E UI: Playwright
- [ ] Добавить/проверить скрипты:
  - `test`
  - `test:watch`
  - `test:coverage`
  - `test:e2e` (при необходимости отдельно для backend/UI)
- [ ] Настроить базовые тестовые конфиги и `setup` файлы.
**Критерии готовности:**
- есть рабочий запуск тестов командой;
- есть 1 пробный тест, который проходит.
**Артефакт:**
- настроенные конфиги и npm-скрипты.
---
## 2) Frontend — Component tests (основной фокус) 
### 2.1 Onboarding форма
- [ ] Тест рендера обязательных полей.
- [ ] Тест валидации (пустые/некорректные значения).
- [ ] Тест успешной отправки (с мокнутым API).
- [ ] Тест обработки ошибки API.
### 2.2 Выбор блюд
- [ ] Рендер списка блюд.
- [ ] Проверка итогового состояния (счетчик/selected list).
### 2.3 Dashboard
- [ ] Loading state.
- [ ] Успешный рендер данных.
- [ ] Empty state.
- [ ] Error state.
**Критерии готовности:**
- минимум 6–8 компонентных тестов;
- покрыты happy path и базовые негативные сценарии.
**Артефакт:**
- тесты рядом с соответствующими компонентами/страницами.
---
## 3) Frontend — Integration tests
- [ ] Сценарий: пользователь заполняет форму → отправка в API (мок) → UI обновляется.
- [ ] Сценарий: ошибка с API корректно показывается в UI.
- [ ] Проверка связки нескольких компонентов на одной странице.
**Критерии готовности:**
- минимум 2 интеграционных сценария;
- тесты проверяют не детали реализации, а поведение глазами пользователя.
**Артефакт:**
- интеграционные тесты страниц (`register`, `dashboard` или `shopping-list`).
---
## 4) Backend — Unit tests (NestJS)
- [ ] Выбрать 1–2 ключевых сервиса.
- [ ] Для каждого метода покрыть:
  - happy path;
  - ошибку/исключение;
  - edge case.
- [ ] Использовать моки репозиториев/внешних зависимостей.
**Критерии готовности:**
- минимум 4–6 unit тестов;
- тесты не ходят в реальную БД/сеть.
**Артефакт:**
- unit тесты сервисов backend.
---
## 5) Backend — E2E tests API
- [ ] Добавить 1–2 e2e сценария через `supertest`:
  - успешный запрос;
  - негативный сценарий (валидация/доступ).
- [ ] Проверить корректные HTTP-коды и структуру ответа.
**Критерии готовности:**
- e2e запускаются отдельно и стабильно;
- сценарии дают уверенность в основных endpoint'ах.
**Артефакт:**
- e2e тесты API.
---
## 6) Playwright — пользовательский flow
- [ ] Сценарий: `registration → onboarding → dashboard`.
- [ ] Проверить:
  - переходы между страницами;
  - отображение ключевых данных на dashboard;
  - что flow завершается без ошибок.
- [ ] Добавить ожидания на видимые элементы (без хрупких селекторов).
**Критерии готовности:**
- минимум 1 стабильный e2e UI сценарий;
- тест проходит несколько запусков подряд.
**Артефакт:**
- Playwright e2e тест критического flow.
---
## 7) Стабилизация и итог этапа
- [ ] Убрать flaky-поведение (тайминги, нестабильные селекторы, лишние ожидания).
- [ ] Прогнать все тесты подряд (frontend + backend + e2e).
- [ ] Зафиксировать короткий итог: что получилось, что осталось улучшить.
**Definition of Done (этап завершен):**
- frontend: 8–10 тестов (component + integration);
- backend: 4–6 unit + 1–2 e2e;
- playwright: 1 критический e2e flow;
- все тестовые команды выполняются и проходят стабильно.

- [ ] **Backend unit-уровень:** вынести расчёт калорий в отдельный модуль/сервис и покрыть unit-тестами (happy path, error, edge case).
- [ ] **Финальная стабилизация Stage 5:** после закрытия пунктов выше прогнать `npm test`, `npm run test:api:e2e`, `npm run test:e2e` без skip.
---
## Фокус обучения на этапе
Главная цель — не «набить много тестов», а научиться:
- выбирать правильный уровень теста;
- писать тесты, которые читаются и не ломаются от мелких рефакторингов;
- покрывать самые важные бизнес-сценарии.
